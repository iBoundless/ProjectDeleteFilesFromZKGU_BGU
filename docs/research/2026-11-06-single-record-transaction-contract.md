# Контракт транзакции одной записи — не реализация

Статус: **не допущено к применению**. Серверный запрет в форме должен оставаться
на входах очистки/восстановления и в низкоуровневых процедурах записи. Этот
контракт не устанавливает проверенного порядка блокировок и не является BSL.

## Обязательные условия одной операции

1. Проверить авторизацию операции, идентичность исходного экземпляра ИБ и
   области и целостность соответствующего архивного файла. Не допускается
   пропуск проверки для копии базы с совпадающими UUID и константами.
2. Для одной записи начать транзакцию. До получения объектов и чтения их
   содержимого получить доказанно совместимые с типовым кодом блокировки для
   всех изменяемых сущностей. Для версии — также её владельца и набор версий,
   если это необходимо для взаимодействия с типовыми операциями. Порядок и
   пересечение блокировок по владельцу и ссылке пока не доказаны.
3. Под блокировкой заново получить объекты, проверить существование, владельца,
   тип хранения, текущую версию и хеш. Для очистки несовпадение хеша означает
   отказ от изменения; для восстановления непустое отличающееся содержимое —
   конфликт. Отсутствие карточки владельца — ошибка с откатом, не успех.
4. Записать содержимое и необходимые реквизиты карточки, учитывая подписки.
   Для исторической версии требуется сохранить реквизиты карточки текущей
   версии. Служебные флаги подавления обработчиков нельзя использовать до
   проверки влияния на обмен и очередь извлечения текста.
5. Прочитать записанные значения из базы и проверить необходимые инварианты
   внутри транзакции. Зафиксировать только после всех проверок; исключение на
   любом шаге приводит к откату и повторной передаче ошибки. Не публиковать
   успешный результат до фиксации. Запись протокола после фиксации не должна
   превращать уже совершённую операцию в ложное сообщение об откате.

## Критерии для снятия запрета

- Реальный тест принудительной ошибки после записи версии и подписок и до
  фиксации проверяет перечитанные данные, карточку и затронутые регистры.
- Два сеанса воспроизводимо проверяют запись той же версии, смену текущей
  версии и владельца. Операции не теряют данные и не оставляют частичных
  изменений при ожидании, тайм-ауте и взаимоблокировке.
- Для старой и текущей версии отдельно проверены чистка и восстановление,
  включая реквизиты карточки и регистрацию изменений в обмене.
- Испытаны две целевые конфигурации, клиентские контексты, разделённая ИБ с
  двумя областями, неверная база, в том числе клон, и отказ при неизвестной
  идентичности. Синтаксическая и статическая проверки не заменяют эти испытания.

До выполнения критериев нельзя объявлять транзакцию безопасной, снимать
проверку `ПроверитьБезопасностьИзмененияДанных` или распространять старую EPF.
