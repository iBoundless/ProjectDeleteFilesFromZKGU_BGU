## Архитектура существующего сценария

1. Объект обработки — таблица `ОбрабатываемыйОбъект` со структурой `Вид`, `Ссылка`, `АдресаАрхивируемых`; виды объектов перечислены в `ГруппировкиОбъектовДО()` и запросах `ТекстЗапроса_*` модуля объекта.
2. Для каждого вида выполняется запрос, который выбирает объект ДО и его двоичное содержимое (например, `ХранилищеЭлектронныхПредставленийРегламентированныхОтчетов`, `СодержимоеТранспортныхКонтейнеров`).
3. Архив — **не zip**, а каталог на компьютере пользователя:
   - файлы копируются в подкаталоги, вычисляемые по владельцу/периоду (`ПолучитьПолныйПуть`);
   - длинные имена сокращаются (`ПолучитьКороткоеИмяФайла`, `КаталогДлинныхИмен`);
   - в корне каталога ведётся `catalog.xml` с историей сеансов (`ЗафиксироватьИсториюАрхивации`, чтение — `ЗагрузитьИсториюКаталога`);
   - запись файлов выполняется **на клиенте** через `НачатьЗапись` (`ПереместитьДанныеВАрхив_ЗаписатьФайлПослеСозданияКаталога`), двоичные данные передаются через временное хранилище.
4. Признак архивности хранится в собственном независимом регистре `РегистрСведений.ПризнакиАрхивированияФайловДОСКонтролирующимиОрганами` (измерения `Объект`, `ИмяФайла`, `Владелец`, ресурс `Архивный`).
5. Очистка (режим «Очистить») записывает пустое `ХранилищеЗначения` в реквизит-хранилище и `Размер = 0`; для регистров — пустую строку/хранилище. Восстановление читает файл из каталога и записывает содержимое обратно.
6. Для присоединённых файлов ЭДО используется:
   - жёсткая карта `ВидыОбъектов_ПрисоединенныеФайлы` (только `ТранспортноеСообщениеПрисоединенныеФайлы`, `ТранспортноеСообщениеКонтейнерыПрисоединенныеФайлы`, `ПерепискаСКонтролирующимиОрганамиПрисоединенныеФайлы`);
   - чтение `ОбщегоНазначенияЭДКО.ПрикрепленныеФайлыКОбъектуИзСправочника(...)`;
   - чтение содержимого `РаботаСФайлами.ДвоичныеДанныеФайла(...)`;
   - запись `РаботаСФайлами.ОбновитьФайл(...)` с содержимым из временного хранилища.
7. Ограничения существующего сценария:
   - нет универсального `Справочник.Файлы` / `Справочник.ВерсииФайлов`;
   - нет контроля целостности архива (хешей/размера при восстановлении);
   - архив — набор файлов, а не самодостаточный контейнер;
   - карта присоединённых файлов ЭДО не покрывает прочие справочники `*ПрисоединенныеФайлы`;
   - регистр `ПризнакиАрхивирования...` имеет определяемый тип только по ЭДО-владельцам и для произвольных файлов не подходит.

## Что переиспользуется в новой доработке

- Отдельная команда и отдельная форма: существующая `Основная` и её сценарий не переписываются.
- Стиль работы: копирование файлов в выбранный каталог, отдельный манифест, явные команды «архивировать / проверить / очистить / восстановить».
- Очистка — только содержимого при сохранении карточки и связей (как в существующем режиме «Очистить»), без физического удаления элементов справочников.

## Что добавлено

- Универсальный обход `Справочник.Файлы` + `Справочник.ВерсииФайлов` (все версии) и всех справочников `*ПрисоединенныеФайлы` с реквизитами `ФайлХранилище`/`ТипХраненияФайла`.
- Манифест сеанса в формате JSON с SHA-256 каждого файла, размером, владельцем, версией и путём внутри архива.
- Проверка архива повторным чтением и сверкой SHA-256.
- Перед очисткой — повторное чтение текущего содержимого и сверка с манифестом.
- Восстановление с проверкой конфигурации, существования объекта и конфликтов содержимого.
- Поддержано только хранение `ВИнформационнойБазе`; тома, встроенное/внешнее хранилище двоичных данных блокируются с явным сообщением.

## Регрессия существующего сценария

Исходные модули не изменяются, кроме добавления кнопки открытия новой формы в `Основная`. Существующие команды, запросы и формат `catalog.xml` остаются прежними.
