# Прогресс архивирования Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Показывать существующую форму прогресса во время архивирования и обновлять её после каждой записи.

**Architecture:** Клиентский цикл формы `ВсеФайлы` открывает `ФормаПрогресс`, отправляет процент/текст через существующие события и закрывает итоговым событием. Не меняются серверные операции и защитный запрет.

**Tech Stack:** 1С BSL, управляемые формы, Python unittest, конфигуратор 8.3.27.2214.
**Spec:** `docs/superpowers/specs/2026-11-06-archive-progress-design.md`

## Global Constraints

- Не снимать серверный запрет очистки/восстановления.
- Не объявлять промежуточную отмену реализованной.
- Проверка UI в клиенте отделена от статической проверки и сборки.
- Файл проекта не является Git-репозиторием; коммиты не создавать.

## Review Focus

- Индекс и имена текущего файла: корректны при пропусках — тест шага 1.
- Завершение при ошибке и после последней записи — тест шага 1.
- Реальное обновление окна при серверных вызовах требует клиентской проверки, не заявляется доказанным статически.
