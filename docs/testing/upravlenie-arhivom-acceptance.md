# Чек-лист приёмки: `УправлениеАрхивомПрисоединенныхФайловОчисткаИВосстановление.epf`

Статус: подготовлен 07.11.2026. Выполнять **только на копии** информационной
базы. Рабочую базу и `hlev` не изменять.

Предмет проверки — отличия новой обработки от прежнего режима «все
присоединённые файлы»:

1. прогресс-бар при анализе, архивировании, проверке, очистке и восстановлении;
2. отбор по одному периоду (`СтандартныйПериод`) на этапе анализа и
   архивирования;
3. штатная отметка БСП «файл перенесён в архив» после очистки и её снятие при
   восстановлении;
4. исходная `СозданиеАрхиваДокументооборота.epf` больше не содержит режим
   «все присоединённые файлы».

## 0. Подготовка

- Копия базы с разделением данных, сеанс в области `25`.
- Не менее трёх файлов «В информационной базе»:

  ```bsl
  ВЫБРАТЬ ПЕРВЫЕ 20
      Версии.Ссылка,
      Версии.Владелец,
      Версии.Владелец.ВладелецФайла КАК ВладелецФайла,
      Версии.НомерВерсии,
      Версии.Размер,
      Версии.ДатаСоздания
  ИЗ
      Справочник.ВерсииФайлов КАК Версии
  ГДЕ
      Версии.ТипХраненияФайла = ЗНАЧЕНИЕ(Перечисление.ТипыХраненияФайлов.ВИнформационнойБазе)
      И Версии.Размер > 0
      И НЕ Версии.ПометкаУдаления
      И НЕ Версии.Владелец.ПометкаУдаления
  ```

- Состав выборки (записать заранее):
  - **A** — файл, дата документа-владельца которого попадает в проверяемый
    период;
  - **B** — файл, дата документа-владельца которого **вне** периода;
  - **C** — файл без версий (`Справочник.Файлы` с пустой `ТекущаяВерсия` и
    `Размер > 0`), если такой есть в базе.
- Свободный каталог на клиенте для архива.
- Записать исходные `Размер` и SHA-256 содержимого для A, B, C.

## 1. Исходная обработка

| Шаг | Ожидание |
|---|---|
| Открыть `build/СозданиеАрхиваДокументооборота.epf` | Открывается форма «Основная» без кнопки «Все присоединенные файлы» |
| Проверить командную панель | Команды `ВсеФайлы` нет; вкладки «Архивация» и «Восстановление» на месте |
| Выполнить штатный сценарий 1С-Отчётности до «Анализ» | Работает как раньше |

## 2. Новая обработка: открытие и каталог

| Шаг | Ожидание |
|---|---|
| Открыть `build/УправлениеАрхивомПрисоединенныхФайловОчисткаИВосстановление.epf` | Сразу открывается форма «Все присоединённые файлы» (DefaultForm), отдельного окна прогресса нет |
| Осмотреть форму | Видны: каталог архива, **период**, сеанс, «Только текущие версии». Группа прогресса **скрыта** |
| Указать каталог → «Проверить каталог» | «Каталог доступен для записи» |

## 3. Период

| # | Действие | Ожидание |
|---|---|---|
| 3.1 | Период не заполнен → «Анализ» | В логе: «Период отбора: с начало не ограничено по окончание не ограничено». В очередь попали A, B и C |
| 3.2 | Задать период, включающий дату документа A и исключающий B → «Анализ» | В логе период и объём; записей B в объёме нет. **Проверить, что поле периода не исчезает** во время анализа (оно вне группы прогресса) |
| 3.3 | «Архивировать» с тем же периодом | В `manifest.json`: `periodStart`/`periodEnd` заполнены; в `records` нет записей B |
| 3.4 | Открыть `manifest.json` | `configName = "УправлениеАрхивомПрисоединенныхФайловОчисткаИВосстановление"`, `formatVersion = 2` |

Примечание. Если у владельца нет реквизита `Дата` (справочник-владелец), берётся
`ДатаСоздания` файла; если нет и её — запись не проходит отбор, только когда
период задан.

## 4. Прогресс

| # | Действие | Ожидание |
|---|---|---|
| 4.1 | «Анализ» на объёме от сотни файлов | Появляется полоса прогресса и подпись; подпись меняется по справочникам («Проанализировано N из M: Справочник.…»); по завершении группа скрывается |
| 4.2 | «Архивировать» | Сначала подпись «Формирование очереди архива» (очередь строится одним вызовом), затем «Выполняется архивирование» с полосой «Обработано N из M»; после манифеста группа скрывается |
| 4.3 | «Проверить архив» | Подпись «Проверено N из M» |
| 4.4 | «Очистить содержимое» | Сначала прогресс проверки архива, затем прогресс очистки; оба завершаются скрытием группы |
| 4.5 | «Восстановить» | Полоса растёт, скрывается по завершении |

Недопустимо: полоса замирает на 0 % до конца операции; группа прогресса остаётся
видимой после завершения; открывается отдельное окно прогресса.

## 5. Очистка и отметка «архивный»

Перед очисткой: архив проверен (`verified = true`).

| # | Действие | Ожидание |
|---|---|---|
| 5.1 | «Очистить содержимое» → подтвердить | По каждой записи «Очищено»; в логе итоги; ошибок нет |
| 5.2 | Открыть `Справочник.Файлы` → текущая версия файла A | `Размер` версии = 0; запись `ХранилищеФайлов` отсутствует |
| 5.3 | Открыть форму версии файла A (`Справочник.ВерсииФайлов.Форма.ВерсииФайла`) | Видна штатная отметка «перенесён в архив» (иконка архива); `ДатаПереносаВАрхив` заполнена |
| 5.4 | Открыть файл A из карточки владельца | Штатное сообщение БСП «Файл находится в файловом архиве. Данные файла недоступны…» |
| 5.5 | Проверить `УсловноПеренесенВАрхив` у версии A | `Ложь` (никогда не `Истина`) |
| 5.6 | Файл C (без версий): очистка | «Очищено», но в строке результата и в логе — «Отметка архива недоступна: у файла нет версий» |
| 5.7 | Повторить очистку | «Очищено: 0, пропущено: N»; отметки не меняются |
| 5.8 | Очистка более 500 файлов | Таблица результатов показывает результаты очистки, а не строки проверки архива: таблица очищается после проверки |

## 6. Восстановление

| # | Действие | Ожидание |
|---|---|---|
| 6.1 | «Восстановить» | «Восстановлено» по всем записям; ошибок нет |
| 6.2 | Открыть файл A из карточки владельца | Файл **открывается** (не «Данные файла недоступны» и не «Ошибка при извлечении файла из Zip-архива») |
| 6.3 | Форма версии A | Отметка «перенесён в архив» **снята**, `ДатаПереносаВАрхив` = пустая дата |
| 6.4 | Сверить SHA-256 и `Размер` A и C с исходными | Совпадают |
| 6.5 | Повторить восстановление | «Восстановлено: 0, пропущено: N» |
| 6.6 | Изменить содержимое файла вне обработки и восстановить | «Конфликт»; новое содержимое не перезаписано |

Порядок 6.2/6.3 важен: если снять отметку после записи содержимого, БСП начнёт
распаковывать файл как zip и выдаст «Ошибка при извлечении файла из
Zip-архива». Появление этой ошибки означает нарушение порядка операций.

## 7. Негативные проверки

Перенесены из `docs/testing/bgu-area25-protocol.md`, раздел «Негативные
проверки»: чужая область, чужой `infobaseId`, непроверенный архив,
повреждённый/удалённый файл архива, смоделированный отказ записи. Ожидания те
же.

Дополнительно для новой обработки:

| Проверка | Действие | Ожидание |
|---|---|---|
| Манифест прежней сборки | Взять каталог сеанса, созданный `СозданиеАрхиваДокументооборота.epf` | Отказ: «Манифест создан в другой конфигурации» (сравнение `configName`) |
| Период после архивирования | Изменить период и нажать «Проверить архив» / «Очистить» / «Восстановить» | Операции идут по манифесту сеанса, период на них не влияет |

## 8. Результат

Заполнить `tests/acceptance-matrix.md`: строки про прогресс, период и отметку.
До прогона на копии их статус — «не выполнялось».

Критерии остановки — как в `docs/testing/bgu-area25-protocol.md`: содержимое
исчезло без строки в манифесте; после отката размер/содержимое отличаются от
исходных; затронута запись вне манифеста; чужой `dataArea`/`infobaseId` прошёл
проверку.
